## 心法：先想"这是哪一类论文的图"，再选布局

很多人用这个 skill 时输出全是"AI 风圆角矩形拼图"——根源是直接套布局模板。
**真实论文的图是"图种 × 布局"双维度决定的**：同样是分层结构，CNN 论文画成带透视的特征图堆叠，系统架构画成层带，分类法画成树。布局只决定骨架，**图种决定皮肤**。

所以工作流的第一步永远是先识别图种（见下表），再选布局。

### 图种速查 —— 决定"皮肤"

| 图种线索（用户提到的关键词） | 必备视觉元素（缺了就不像那个领域的论文） |
| ---------------------------- | ---------------------------------------- |
| CNN / ViT / feature map / 图像分类 / 检测 / 分割 | 透视特征图（带厚度的平行四边形堆叠）、通道数标注 `C×H×W`、输入/输出位置放真实图像或缩略图占位 |
| Transformer / attention / LLM / encoder-decoder | 多层堆叠半透明矩形 + 右上角 `× N`、Q/K/V 用三种小色块拼接、Add&Norm 用窄条 |
| Pipeline / preprocessing / 端到端流程 | 步骤间放数据样例缩略图（不是只有箭头）、步骤序号徽章、每步有"输入→输出"形态标注 |
| Ablation / baseline vs ours / 消融 / 对比 | "Ours" 整行/列用 accent 高亮、最佳数字加粗或加圈、其他方法保持低饱和不抢眼 |
| Training / inference / 训练 vs 推理 / 双阶段 | 双轨布局，两轨用两个明显不同色系（不是同色调的深浅）、共享权重用虚线连 |
| System / microservice / 软件架构 | 模块按"层带"组织（UI/逻辑/存储），跨层箭头标 protocol（REST/gRPC/SQL/tensor）|
| Biology / cell / drug / 临床 / 实验 | 用图标/示意图元（试管、细胞、分子、器官轮廓）代替部分纯矩形、避免 ML 风格冷色 |
| Robotics / control / 反馈 / 闭环 | 闭环箭头明显加粗 + accent 色、传感器/执行器用专门图形（圆角梯形/三角形）|
| Method 概览 / 我们的方法有 N 个贡献 | 放射状或网格 + 中心 hub 用 accent 高亮、卫星块尺寸完全一致 |
| Roadmap / 项目阶段 / 里程碑 | 时间轴 + 卡片上下交错、节点用实心圆+白描边、关键里程碑用 accent |

**如果用户输入里这些线索都没出现** → 当作通用流程/系统图处理，按布局走默认皮肤即可。

## 工作流程（严格按顺序）

```
1. 识别图种（看上面那张表的关键词）
   → 决定用哪些"图形语汇"（见 reference/visual_primitives.md）

2. 识别布局（10 选 1，见下面速查表）
   → 决定整体骨架

3. 阅读 palettes.md，挑一个调色板
   → 不确定就用 Palette 1

4. 阅读 reference/drawing_recipes.md
   → 拿到具体的尺寸/间距/字号"建议值"

5. 阅读 reference/visual_primitives.md
   → 拿到图种专属的图形片段（透视特征图、堆叠层、回环箭头等）

6. 阅读对应布局的 SVG 模板
   → 学骨架，不照抄

7. 自然语言输入务必先回显解析结果给用户确认，再画
   结构化输入直接画

8. 编写 SVG → 用 render_helpers.py validate 自检 → 渲染成 PNG/PPTX
```

## 十种布局速查 —— 决定"骨架"

| ID | 布局       | 何时用                                 |
| -- | ---------- | -------------------------------------- |
| 01 | 分层网络   | 神经网络、阶段内含子块的多阶段流水线   |
| 02 | 水平流程   | 线性算法、简单管线、X→Y→Z 工作流       |
| 03 | 模块系统   | 系统架构、软件组件、"谁与谁通信"       |
| 04 | 层级树     | 分类法、决策树、方法/组织层级          |
| 05 | 循环反馈   | 迭代方法、训练循环、控制系统           |
| 06 | 双轨对比   | 基线 vs 改进、编码器/解码器、训练/推理 |
| 07 | 网格矩阵   | 消融对比、方法×指标矩阵、能力对照表    |
| 08 | 放射状中心 | 核心+N 个环绕模块、"N 个关键贡献"      |
| 09 | 泳道流程   | 按角色/阶段拆分的流程、多团队流水线    |
| 10 | 时间轴     | 研究路线图、项目阶段、里程碑时间线     |

布局不必死磕一种。允许混合，例如分层网络主体 + 末端接一条循环反馈曲线，或者双轨布局里嵌入一个小型放射状子图。**只要逻辑清晰，怎么组合都行。**

## 输入处理

| 输入类型     | 处理方式                                              |
| ------------ | ----------------------------------------------------- |
| 自由散文     | 提取实体+关系 → 回显结构化形式 → 等用户确认 → 渲染   |
| 编号步骤清单 | 按结构直接映射，不必再回显                            |
| 直接给一张参考图说"按这个画" | 先口述你打算照搬什么、改什么，等用户确认再画 |

对于自然输入，**一定要先回显解析再画**。这一步省不得，否则布局选错重画成本极高。

## 重要规则

- **PNG 输出 dpi=400** 达到期刊水准。
- **语言匹配**：用户主要用中文 → 中英文混合标签（技术术语用英文）；用户主要用英文 → 全英文。
- **字体**：`font-family` 必须把 CJK 字体写在最前（`'Noto Sans CJK SC', 'SimHei', 'Times New Roman', serif`），否则中文渲染成豆腐框。纯英文图可以 TNR 在前。
- **特殊符号**：★ ✓ ✗ ① ↻ 这些字符在 cairosvg 里可能渲染失败，**一律用 SVG 图元绘制**（见 `visual_primitives.md`）。Unicode 数学符号（θ ∇ σ² ⟨⟩ ≤）正常字体都支持，可以直接用。
- **SVG 是唯一真相**。PNG 和 PPTX 都从 SVG 生成。**绝不**手动编辑 PNG/PPTX，要改就改 SVG 重新渲染。
- **参考模板看骨架，不看内容**。模板里的具体文字、数值、技术术语都是占位，你要学的是图框排列方式、配色搭配、连线走向。
- **不要过度套模板**。模板是 10 个起点，不是 10 个牢笼。看完模板后按用户的具体需求灵活组合、增减元素。

## 自检清单

每张图画完，逐项过一遍。任何一条不过就重画或修改。

- [ ] **图种识别正确**：用户提到 CNN / Transformer / 对比 / 训练-推理 等关键词时，图里有没有对应的"皮肤"元素（特征图、堆叠层、accent 高亮、双色轨）？不能只画矩形糊弄。
- [ ] **没有悬空分支**：每条路径都终止或汇合到某个节点。
- [ ] **文字不重叠不出框**：每个容器的标题、模块标签、注释，都在自己的形状内部，不压边界、不压相邻文字。
- [ ] **箭头清晰**：marker-end 都有定义且被引用，方向正确指向目标；虚线和实线视觉上明显区分。
- [ ] **没有豆腐框**：含中文时 font-family CJK 字体在最前；★✓✗ 等用 SVG 图元而非字符。
- [ ] **整体风格一致**：圆角半径、字号梯度、边框粗细在同一张图里保持一致（一张图里别既有 rx=4 又有 rx=14）。
- [ ] **尺寸均衡**：同层级容器尽量等高、同类模块尽量等宽，没有"一块特别大、其他特别小"的局部失衡。
- [ ] **所有元素在 viewBox 内**。
- [ ] **跑通验证器**：`python render_helpers.py validate <svg>` 输出 0 problem。

如果任何一条不满足 → 改 SVG → 重新验证 → 重新渲染。**不要把不合格的图交给用户。**
