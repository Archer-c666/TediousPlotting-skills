# Timeline Flow 流光时间线 — 使用说明

## 何时使用
带时间戳的离散事件，事件可归属到不同通道/角色/类型。最适合追溯事件序列、看不同主体何时活跃、对比多线程的并行进展。

典型场景：项目甘特图、团队工作时间线、用户行为序列、系统事件日志、医学治疗时程、产品发布路线图、新闻事件年表。

## 必填占位符

通用部分：`TITLE / EYEBROW / H1_LEFT / H1_EM / H1_RIGHT / LEDE / META_TITLE / META_SUB / META_DATA / DATA / COLORS`

本图特有：

| 占位符 | 填什么 | 示例 |
|--------|--------|------|
| `{{ROOT_NAME}}` | 详情面板默认状态的名字 | `Project Atlas Q2` |
| `{{NOW_DATE}}` | "现在"参考线，ISO 字符串或 `null` | `"2024-06-15"` 或 `null` |

注意：本图 `{{UNIT}}` 不使用（时间单位已固定为天），可省略或填空。

## 数据结构

事件数组，每条：

```javascript
[
  {
    "channel": "Alice",                  // 通道（行）名
    "start": "2024-01-01",               // ISO 日期或日期时间
    "end":   "2024-01-15",               // 结束（>= start）
    "category": "design",                // 类别（用于上色和过滤）
    "label": "Wireframes",               // 显示在事件块上的文字（自动截断）
    "meta": { "owner": "Alice" }         // 可选附加字段
  }
]
```

`channel` 决定垂直位置（哪一行）。`category` 决定颜色（用 `{{COLORS}}` 映射）。

## COLORS 映射

```javascript
{
  "design":   "#b88ec2",
  "dev":      "#6a9bd1",
  "research": "#7fb8a4",
  "ops":      "#f0c674"
}
```

没有映射的类别会自动用分类调色板补齐（最多 7 种）。

## 交互

| 操作 | 结果 |
|------|------|
| 悬停事件块 | tooltip 显示标题/起止/时长；其他事件变暗；通道标签和行背景高亮 |
| 悬停通道标签 | 整行事件高亮，其他变暗；右侧面板显示该通道汇总 |
| 点击类别图例 | 切换该类别显示/隐藏 |
| 在底部概览条上拖拽刷选 | 主视图时间窗口缩放到刷选范围 |
| 点击 "Reset zoom" | 恢复全时间范围 |

## 关键设计决策

- **概览条 + 主视图**：双层时间轴是处理"既要看全貌、又要看细节"的标准方案（Shneiderman 的 overview+detail）。概览条始终显示全部事件的位置，刷选框告诉你当前缩放窗口在哪。
- **事件块宽度=时长**：长度通道编码持续时间，是定量编码精度最高的通道（Cleveland & McGill）。
- **行高 ≥ 28px**：保证悬停命中区域足够，移动端也能用。
- **块内 label 自动截断**：宽度不够 30px 不显示文字，避免溢出；用 `…` 截尾。
- **"现在"线**：可选的赤陶色虚线，给时间提供锚点参考。设为 `null` 隐藏。

## 定制需求

| 用户需求 | 怎么做 |
|---------|--------|
| 隐藏概览条/刷选 | 删除 `.overview` 节点 + 移除 `brushG` 和 `brushed()` 相关代码 |
| 改"现在"线颜色 | 改 CSS `.now-line` 的 `stroke` 和 `.now-label` 的 `fill` |
| 添加事件依赖箭头 | 在 `events` 数据中加 `dependsOn: "事件id"`；用 `d3.linkHorizontal` 在 `eventsG` 之前画 path |
| 通道分组（多个团队） | 按 `team` 字段把 `channels` 排序，在分组间插入 `<line>` 加粗分隔线 |
| 显示里程碑（瞬时事件） | 用 `start === end` 的事件；render 时检测并改成菱形而非矩形 |
| 时间单位改成小时/分钟 | 把 `d3.timeFormat("%b %d, %Y")` 换成 `"%H:%M"`；调整 `tickCount` |
| 隐藏类别图例 | 删除 `#catLegend` 节点和初始化循环 |
| 事件块圆角更明显 | 改 rect 的 `rx` 值（默认 2，可到 6） |

## 限制

- 推荐 ≤ 15 通道（行）。再多会让概览失去意义；建议改用分组折叠
- 推荐 ≤ 500 事件。超出后渲染卡顿（特别是带文字标签时）
- 时间跨度过大（多年）+ 事件密集 → 概览条上事件重叠成实色块。考虑按月聚合
- 同通道事件**重叠**（同一行内两段时间重合）会导致后绘制的覆盖前面的。如果你的数据真有重叠，可以加 y 偏移或者用更复杂的"swim lane"布局——本模板不自动处理

## 数据准备建议

如果你的数据是事件流而非"start+end"（每条只有一个时间戳），可以：

```javascript
// 假设原数据：每个事件一个时间点
const raw = [{ts: "2024-01-15", actor: "Alice", action: "commit"}, ...];

// 按 actor 分组，把连续 commit 合并为"活跃区间"
// 或者每个事件 +1 天作为可见的最小块
const events = raw.map(d => ({
  channel: d.actor,
  start: d.ts,
  end: new Date(new Date(d.ts).getTime() + 86400000).toISOString(),
  category: d.action,
  label: d.action
}));
```

## 已知陷阱

- **时区**：纯日期字符串 `"2024-01-01"` 在 UTC-8 时区会解析成前一天。锚定时间用 `"2024-01-01T12:00:00"` 中午。
- **end < start**：会渲染成负宽度（不可见）。预处理时 `Math.max(start, end)` 或验证后丢弃。
