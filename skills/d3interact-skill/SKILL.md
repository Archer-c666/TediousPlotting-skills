## 什么情况下使用本 skill

仅当以下三条**全部**成立时触发：

1. 用户想要的是**交互式可视化**（悬停、点击、下钻、刷选），而非静态图表
2. 数据形态匹配本 skill 覆盖的某一类可视化习语（层级、流向、网络、矩阵、多维、地理、周期、二维交叉、时序事件），**或它们的变体 / 组合**
3. 输出是**独立可运行的 HTML 文件**

**不适用：** 

    一般的月销售条形图、简单折线趋势图、单一散点图

**判断速查：**

| 用户问什么                                    | 适用？ |
| --------------------------------------------- | ------ |
| "做一张可以点击下钻的层级图"                  | 是     |
| "我想看资金从哪儿流到哪儿，要能 hover 看明细" | 是     |
| "比较5家公司在6个维度上的画像"                | 是     |
| "给我画个柱状图"                              | 否     |
| "做一份静态信息图打印出来"                    | 否     |

## 核心理念：先学设计语言，再按数据构建

这是使用本 skill 最重要的一条。**本 skill 教的是一套设计语言和一套选图思路，不是一摞等你照抄的模板。**

- **`references/design-system.md` 是唯一真源。** 配色、字体排印、布局架构、动效、交互原语、无障碍——全部原理都在这里，而且每条规则都讲清了背后的感知科学或排印依据。**先把它内化，再动手。** 你产出的任何东西都应当贯彻它。
- **`references/selection-guide.md` 教你为数据挑对编码。** 它讲每种习语的适用条件、强项、弱项、扩展上限——目的是帮你判断"这份数据该用哪种视觉编码"，而不是给你一个封闭的类型清单去对号入座。
- **`assets/<图类型>/` 里的模板只是参考样例和起点，不是要照搬的牢笼。** 它们演示了设计系统如何落到某一种习语上。读它是为了学结构和手法——HTML 骨架怎么搭、交互怎么接线、动效怎么错峰——**而不是把数据硬塞进去然后改几个字交差**。模板缺失时，本 skill 依然成立：你完全可以只凭设计系统 + 选图指南从零构建。
- **习语是词汇，不是模具。** 鼓励你为真实数据**适配**习语、**组合**两种习语、或在设计语言内**创造变体**——只要配色 / 字体 / 布局 / 动效 / 交互 / 无障碍这套语言守得住。
- **评判成品的标准**是这四条，而**不是**"有没有填满某个模板"：

  1. 是否忠实于用户的真实数据；
  2. 是否贯彻了 `design-system.md` 的设计语言；
  3. 交互是否完备（悬停高亮、tooltip、联动面板、错峰入场……）；
  4. 是否无障碍（灰度可区分、对比度达标、键盘可达）。

## 工作流

```
1. 探数据形态
   用户已点名图类型 → 直接进入第2步。
   用户只描述了数据和需求 → 先问清楚：
   - 数据是层级的（树状）、网络的（图状）、流向的（多阶段）、还是表格的（多列属性）？
   - 主要分析任务是什么？比较占比？发现聚类？追溯路径？看时间分布？
   - 数据规模？（叶节点数、节点数、记录数、维度数）

2. 读 references/selection-guide.md
   它列出每种习语的适用条件、强项、弱项、扩展上限。先读完，建立"数据形态 → 视觉编码"的判断力。

3. 推荐1-2个候选并说明理由
   不要静默挑一个直接开做。给用户两个有理有据的候选：
   > 根据你的描述，建议：
   > 首选：旭日图——你的数据是3层树，用户既想看占比又想下钻，这正是旭日图最擅长的角度编码 + 径向下钻。
   > 备选：矩形树图——如果你更关心"哪些叶节点最大"而非层级本身，矩形树图的面积编码会更精确。
   > 你倾向哪个？
   如果标准习语都不完美贴合，明说，并提出适配 / 组合 / 变体方案。让用户拍板，但功课你已经做完了。

4. 内化设计系统，再按数据构建（关键步骤）
   先读透 references/design-system.md：
     · 配色系统（基础色板、分类/顺序/发散色板、配色十条）
     · 字体排印（Fraunces + Inter Tight + JetBrains Mono 三件套）
     · 布局架构（非对称头部、三栏舞台、构图原则）
     · 交互原语（悬停高亮、tooltip、下钻、联动面板、图例过滤）
     · 动效（时间常量、缓动、错峰入场、数值插值）
     · 无障碍（色觉、对比度、键盘、ARIA）

   然后，如果选中习语在 assets/<图类型>/ 下有模板：
     · template.html —— 当作结构参考和起点来学，不是照抄目标
     · notes.md      —— 该习语的定制提示、已知限制
     · sample-data.json —— 仅在用户未提供数据时用作回退示例

   接着按设计语言构建可视化：为真实数据组织布局、接好交互、错峰动效、补全无障碍。
   数据需要时大胆适配 / 组合 / 创造变体——守住设计语言即可。

5. 完成自检清单后输出
```

## 输出的构成要素

每一个成品都应包含下面这些**信息要素**——它们对应 `design-system.md` §3.2 的非对称头部结构与图表区。

> **注意：** 这些是你需要**组织和填充的内容槽位**，**不是**必须逐字替换的 `{{占位符}}`。无论你是参考某个模板还是从零搭页面，都应当把这些信息表达清楚。不要让成品里残留"climate""TREEMAP"之类与当前数据无关的样板字样。

| 要素       | 填什么                           | 示例                                                   |
| ---------- | -------------------------------- | ------------------------------------------------------ |
| 标签页标题 | 浏览器标签页标题                 | `全球碳排放结构 2023`                                |
| 顶部小标签 | 等宽大写的上下文标签             | `可视化习语 · TREEMAP · 气候数据`                  |
| 主标题     | 左段 + 斜体高亮中段 + 右段       | `全球碳排放的` *`结构性失衡`* `——按区域拆解` |
| 引导文     | 1-2 句引导，结尾给一个交互提示   | `点击任意区块下钻到细分行业。悬停看具体数值。`       |
| 右上元信息 | 主标题 / 副标题 / 数据来源标注   | `Climate Atlas 2025` · `IEA / 2023`               |
| 单位       | 数值单位短串                     | `GT CO₂` 或 `users` 或 `$M`                     |
| 数据       | 真实数据字面量（结构按习语而定） | 见各 `assets/<图类型>/notes.md`                      |
| 分类色映射 | 类目到色相的映射                 | `{ "Asia": "#e36a4a", "Europe": "#7fb8a4" }`         |

各习语特有的数据结构与定制点，详见对应 `assets/<图类型>/notes.md`（若模板缺失，参照 `selection-guide.md` 里每种习语给出的"示例数据结构"自行搭建）。

## 自检清单

输出前请逐条对照。检查是**忠于数据、贯彻设计语言、交互完备、无障碍**。

### 数据与内容

- [ ] 用户给的真实数据**原样使用**——不要伪造、不要"四舍五入"
- [ ] 用户没给数据时，用对应习语的 `sample-data.json`（或自行造的示例）并**主动告知用户**这是示例
- [ ] 图与数据真正匹配——为数据**适配**了习语，而不是把数据硬塞进固定布局
- [ ] 标准习语不完美贴合时，已考虑过适配 / 组合 / 变体，并向用户解释了取舍
- [ ] 数据规模在该习语的扩展上限内（见 `selection-guide.md`），否则向用户提示风险或建议预聚合
- [ ] 标题、引导文、元信息都对齐当前数据主题——没有残留任何样板字样

### 视觉规范（贯彻 design-system.md）

- [ ] 字体只用 Fraunces + Inter Tight + JetBrains Mono 三件套
- [ ] 默认深色主题 + 琥珀色强调（`--accent: #f0c674`），除非用户明确改色
- [ ] 分类色取自 `design-system.md` 的 7 色色板（不要随手编色），且 ≤ 7-8 种
- [ ] 有序数据用明度/饱和度梯度，发散数据用经中性灰的双色——绝不纯红到纯绿
- [ ] 所有数值用等宽字体或 `tabular-nums`
- [ ] 强调色仅用于：焦点元素、悬停态、激活选区、主操作——稀缺为贵
- [ ] 叠了背景氛围两层（径向光斑 + 噪点），图表与背景有图地分离

### 交互完备性

- [ ] 悬停 → 高亮目标 + 其他元素变暗到 18-22% 透明度
- [ ] tooltip 跟随光标（偏移 +18,+18），含名称 + 路径 + 1-3 项数值
- [ ] 右侧详情面板会联动更新（补偿人眼对角度/面积的读数误差）
- [ ] 入场有错峰动画（`delay: i * 12ms`）
- [ ] 数值变化用插值，不跳变
- [ ] 所有过渡 ≤ 900ms，没有阻塞首次交互的长动画

### 无障碍

- [ ] 灰度模式下分类色仍可区分（`filter: grayscale(100%)` 测试）
- [ ] 颜色不单独承载语义（搭配位置/标签/形状），没有红绿单独表义
- [ ] 正文对比度 ≥ 4.5:1
- [ ] 主要交互元素有 `tabindex="0"` 和清晰焦点环
- [ ] 图表容器有 `role="img"` + `aria-label`，详情面板 `aria-live="polite"`

### 代码可运行性

- [ ] 所有内容槽位都填了真实内容，没有残留任何样板/占位文字
- [ ] D3 CDN 链接保留（`https://d3js.org/d3.v7.min.js` 及所需附加包）
- [ ] 数据字面量是合法 JS 对象（注意尾逗号、引号）
- [ ] 直接 `open output.html` 能在现代浏览器跑起来

## 定制对照表

用户提常见调整需求时按这张表对应：

| 用户需求                | 怎么做                                                               |
| ----------------------- | -------------------------------------------------------------------- |
| 改强调色                | 覆盖 `--accent` CSS 变量；同步改 tooltip 色带                      |
| 整体换主题色            | 替换 `categoricalPalette` 数组（见 design-system.md §1.2）        |
| 改浅色主题              | 把 `--bg-0/1/2` 改成浅色 + 把 `--ink/ink-dim` 反色，并重测对比度 |
| 隐藏 tooltip            | 删 `.tip` 节点 + 移除 `showTip` 调用                             |
| 隐藏详情面板            | 把 `.stage` 改成单列 + 删 `.panel-detail`                        |
| 数据条目超上限          | 建议换习语，或预聚合小类目为"其他"                                   |
| 标准习语放不下数据      | 适配（调整层级/聚合）、组合两种习语、或在设计语言内自创变体          |
| 想要打印 / 嵌入静态报告 | 本 skill 不适合；建议生成 SVG 静态图                                 |
| 想要键盘导航            | 给主要 mark 加 `tabindex="0"` + `focus` 样式 + 监听 `keydown`  |
